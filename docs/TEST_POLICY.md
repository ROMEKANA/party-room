# テスト方針と回帰項目

## 実施方法

1. リポジトリのルートで Node.js 24 を使い `npm test` を実行する。`pretest` が Worker をビルドし、`node --test` が `test/` を実行する。ゲームルールは `test/mode1.test.js`、独立したHTTPセッションと保存・互換性は `test/online.test.js`、更新検知と再入室は `test/sync.test.js` が主な入口。追加・変更した挙動には、再現可能な範囲で自動テストを追加する。
2. [ローカル開発環境](../README.md#動かす)を `npm run dev` で起動し、独立したタブまたはブラウザープロファイルでホスト・ゲスト・観戦者を用意する。同名再入室の確認時は、旧接続側も開いたままにする。変更したゲーム進行は開始条件から入力、対戦、最終結果、履歴まで通して確認する。共通機能を変更したときは、各ゲームでも対応する項目を確認する。
3. スマートフォン縦画面で表示と操作を確認する。375px幅などのブラウザーエミュレーションと実機の結果は区別し、端末やブラウザー、画面サイズを記録する。長押しやスリープ防止など端末依存の項目は、確認できた環境を明記する。
4. 実施した確認と結果、実施できなかった項目、残った未確認事項を [作業報告](RELEASE_POLICY.md#作業報告) に記録する。

以下は公開前の回帰確認に使う。共通項目はゲームをまたいで適用する。新しいゲームを追加する際は、ゲーム別の表に開始条件、進行、秘密情報、結果・履歴の確認項目を追記する。

## ゲーム別の回帰確認

### みんなでtier表

| 観点 | 確認項目 |
|---|---|
| 全4モードの開始条件・設定 | 接続中2人以上、参加枠の上限、難易度・枚数とTier数の境界を確認する。tier並び当て・tierお題当てでは親を入力人数から除く。基本・モード・詳細設定、各抽選方法で全Tierに割り当てがあること、難しい設定での端Tierの出現制限を確認する。 |
| お題担当・親・プレイヤー順 | 内蔵お題の採用・再抽選・自由入力、お題候補の表示範囲、ランダムな一巡・役割指名の消費・次戦への交代を確認する。推理モードは右隣を親とし、末尾から先頭への循環、手動指名による並べ替え、シャッフル、切断・退出後の補正を確認する。 |
| みんなでtier表 | 共通順に沿う手番、記入者だけへの手番開始確認、提案・投票権限、早期棄却と全員投票後の正誤判定を確認する。誤答時のライフ減少・正解公開／再挑戦、得点ON／OFF、正答時の配点、結果までの得点非公開、クリア・失敗を確認する。 |
| tier並び当て | 親の入力対象外、配布後の配置と置き直し、全カード・全Tierの提出条件、完全モードと正答率モードの成功・再提出・上限到達、ライフと最後の提出結果を確認する。記入者表示を設定で切り替え、入力中の割当済みTierは許可された親以外の参加者だけが確認できることを照合する。 |
| tierお題当て | カードの指定Tierへの自動配置、親の口頭解答、判定担当と切断時の代行、ライフと最終結果を確認する。記入者表示の設定を切り替え、結果前に親・観戦者へお題を返さないことを確認する。 |
| 全員一致モード | 入力中は自分のカードだけを参照・編集し、配置開始時は共通のカード順になることを確認する。自分の配置だけが見えること、配置中の投稿者表示の切り替え、指定Tierの非公開、全カード・全Tierの確定条件、確定後の表示と変更不可を照合する。全員確定後に一致数、不一致カード、各人の配置・投稿者・指定Tierを確認する。 |
| 重複・結果・保存 | 全4モードで同名・正規化後の同名を拒否し、同時送信でも1件だけ確定することを確認する。対戦やモードに応じた正誤・得点・投票・ライフ・最終盤面が結果と履歴で整合し、完了した対戦につき履歴が1件だけ保存されることを確認する。 |

## 共通の時間管理とタイマーUI

- 4ゲームで同じ開始前・終了時の通信猶予が適用されることを確認する。旧ルームでは1,000ms・800msを使い、ホストの変更がロビー復帰・ゲーム切り替え・再入室をまたいで維持される。ゲスト・観戦者と対戦中のホストは変更できず、履歴保存期間は従来どおり扱う。
- 受付開始直前・開始時刻・締切直前・締切時刻・猶予終了直前・終了時刻を検証する。全員提出、制限時間なし、未提出時の自動行動、古いターンと重複送信をゲームごとに確認する。
- 複数タブで時刻表示と入力可否を比較し、再接続・バックグラウンドからの復帰、結果と演出での表示、画面遷移後の描画停止を確認する。縦画面でバーと各ゲームの操作が1画面に収まることを確認する。

## 共通ルーム管理

| 観点 | 確認項目 |
|---|---|
| 入室と権限 | 観戦者込みで10人まで入室できること、ゲーム・モード別に開始人数と参加上限が適用されることを確認する。ホストとゲストの操作範囲、手動譲渡、退出・切断から猶予経過後の自動交代を確認する。 |
| 名前とアイコン | 新規名の1・8・9文字、空欄、制御文字、日本語・英数字・絵文字のコードポイントと正規化を確認する。旧名の同名復帰、10種類の選択と復元、別セッションへの同期、アイコン重複と変更を確認する。 |
| 再入室 | 同名再入室で順番・ホスト権限・対戦の役割を引き継ぎ、旧接続からの同期・操作を拒否することをロビー、設定、対戦中、結果で確認する。 |
| プレイヤー順・観戦枠 | 開始前の順番とシャッフル、ゲーム・モード変更時の枠再計算、退出後の繰り上がりを確認する。対戦中は開始時の名簿・順番を保持し、新規入室者は観戦する。終了後は次回の参加枠に反映し、対戦時の名簿は維持する。 |
| 切り替え・設定復元 | ホストのゲーム切り替えやロビー復帰が各クライアントに反映され、ゲーム・モード別設定、共通設定が同期し、再入室で復元することを確認する。全員退出・再接続猶予終了後は次の入室がロビーから始まり、永続設定・履歴・お題が保持され、中断対戦は保存されないことを確認する。 |

## データ・通信

| 観点 | 確認項目 |
|---|---|
| 既存データと履歴 | 旧ルーム・旧設定を既定値で補完し、ゲームIDのない旧履歴をTier表として表示することを確認する。全ゲーム／ゲーム別の一覧・詳細、保持期間の変更と期限切れ削除、ホストによる表示範囲ごとの削除を確認する。 |
| 競合・再送 | 画面・対戦・対象カードや候補が変わった古い操作を拒否し、同時操作で状態が分岐しないことを確認する。操作IDが同じ再送の重複適用防止、同時の開始と入退室、同名カードの競合、結果の重複保存防止を確認する。 |
| 同期 | タブをバックグラウンドにしてから復帰し、直ちに同期することを確認する。通信失敗からの再接続、未変更時の応答削減、1クライアント内の同期リクエストの重複、ゲーム切り替え後に非選択ゲームへ定期通信が発生しないことを確認する。 |

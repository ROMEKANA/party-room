# アーキテクチャ

## サーバーとデータ

`server/api.js` が参加、状態取得、操作、履歴、公開バージョンを提供する。認証はタブ単位の接続トークンを使い、同名再入室時は古いトークンを無効にする。`server/game.js` が共通の画面遷移、ホスト権限、ゲームへの操作の振り分けを担当する。画面を移るたびに操作対象のIDが変わる。対戦中は対戦IDと対戦リビジョンも照合する。操作IDを参加者単位で記録して短時間の再送を重複実行しない。

D1の `room` テーブルは単一行で、設定、共通設定、参加者の配列順、現在の画面と対戦をJSONに保存する。`server/store.js` はリビジョンに対する条件付き更新で競合を解決し、結果の保存と状態更新はD1の同一バッチで実行する。入室時と認証済みのルームアクセス時に再接続期限切れを整理する。全員の退出が確定すると対戦と一時状態を破棄し、永続設定を残す。進行中の対戦が破棄された場合は結果を書き込まない。旧ルームで不足しているフィールドは読み込み時に補完し、旧クライアントには進行中のTier表の操作を引き続き受け付ける。

`server/room.js` は現役の在籍者から、ゲーム・モード上限までの参加枠を配列順に求める。ゲーム共通の人数設定は `web/games.js` に置き、モードごとの上限があるゲームは `modeMax` を指定できる。`server/game.js` はルーム更新の中で開始時の参加者を確定し、参加者IDの順序と、その時点のアイコンIDを対戦に保存する。退出済みの対戦参加者の情報は、その対戦の同名復帰用に保持し、在籍数・観戦順・次の参加枠から除く。結果画面は対戦時の名簿と次回の参加枠を個別に参照する。D1の列追加は不要。旧データでアイコンIDが欠けているときは旧色スロットを対応するイラストに変換し、色もない場合は三毛猫を表示する。旧色スロットは接続中プレイヤーの応答判定にも引き続き使う。

`round_history` の既存列をそのまま利用する。JSON内の `gameId` でゲームを識別し、値を持たない旧レコードは `tier` として扱う。Circle & Crossのスナップショットには勝者、経過ラウンド数、参加者ごとの勝数と公開済みの盤面を保存する。期限切れ削除は参加・履歴取得・保存期間変更・結果保存のタイミングで行う。旧Circle & Crossのサイト別D1は、そのサイトで作ったルーム用で、本アプリでは新しい共通ルームで対戦を始める。

Tier表の表示データは `server/visibility.js` と `server/consensus.js` で参加者ごとに制御する。`server/circle.js` は自身の札だけを本人に返し、他の参加者には伏せ札の枚数と公開済みの札だけを返す。

Tier表の開始前の役割指名とプレイヤー順は同じルーム更新で保存する。退出や旧設定の復元時は在籍者を照合し、お題担当が無効ならランダム、親だけが無効なら右隣を補う。対戦開始時は接続中の参加者で役割を決め、開始済みの対戦では保存済みの役割を使う。

### 同時ターン制の対戦

`server/battle.js` の戦闘判定はI/Oを持たない。ターン開始時のステータスで全行動を検証し、敵ごとの攻撃を組み立ててから相殺、防御、被弾上限、エネルギー、勝敗を一括で判定する。クライアントと共用するアクション可否・設定範囲は `web/battle-rules.js` に置く。共通のルームJSONに設定、チーム編成、開始時の参加者、現在のターンの提出と直前の結果を保存する。D1の列追加は不要。

ターンは開始待ち、行動選択、締切猶予、結果表示へ進む。サーバー時刻で開始・締切・結果終了を計算し、認証済みの同期・操作で期限を進める。同期が途絶えた後は、次のターンをその同期時刻に基づいて開始する。クライアントは既存の同期レスポンスの時刻と往復時間で時計を補正し、プログレスバーをローカルで描画する。

行動は共通の接続トークン、画面ID、対戦IDと操作IDに加え、ターン番号とプレイヤーごとの行動変更順を照合する。この操作のみに限り、他の人の提出によって変わった対戦リビジョンを拒否理由にしない。D1の条件付き更新と再読み込みで順序・確定・履歴保存の競合を解決する。APIは提出の有無と本人分の行動だけを返し、他のプレイヤーの行動は確定後に公開する。旧クライアントには新ゲームの対戦と履歴を表示せず、既存の更新通知を使う。

### 職業付き対戦

`job-battle` は元のゲームと別ID・別設定で、行動検証、ターン進行、チーム、カードUI、勝敗、履歴処理を共用する。職業定義と固定設定は `web/battle-jobs.js` に置く。抽選済み候補と選択結果は対戦JSONに保存し、職業選択中の応答は本人の候補・選択内容と全体の確定人数だけを返す。職業確定は画面・対戦ID・接続・操作IDを照合する。対戦リビジョンが他人の確定で進んでいても、本人が未確定なら同じ対戦への操作を受け付ける。全員確定の更新と公開は原子的に行う。

1. ターン開始時のHP・エネルギー・呪い・連続防御回数で行動を検証する。途中で脱落するプレイヤーの確定済み行動も解決する。
2. 敵対する攻撃を相殺し、ガード・かばう・反撃を解決する。反撃ダメージは独立した被弾として追加し、二次反撃は発生させない。
3. 残った被弾を対象別に、ダメージ降順・攻撃者ID昇順で採用する。採用分のダメージと回復を同じHP計算に入れ、0から最大HPまでに丸める。
4. 消費を引いた残量を強奪の原資とする。複数の強奪は攻撃者ID昇順で処理する。被弾上限で減ったダメージも、防御・相殺・反撃で無効にならず届いた単体攻撃なら強奪できる。溜め・渡す・騎士などの獲得を別枠で扱い、受取側の残り容量を越える強奪は行わない。今ターンの獲得分は強奪の原資に含めない。
5. 呪いを付け替え、今ターン付与したものだけを次のターンに持ち越す。結果と勝敗を公開し、終了時に同じトランザクションで履歴を記録する。旧ゲームは従来のダメージ量の上限を使う。

### ナンバークラッシュ

`server/number-clash.js` が手札、山札、場、提出、採点を管理する。ターン開始と締切時刻はバトルと同じ `server/timed-turn.js` を使用する。対戦ID・ターン番号・本人の変更順でカード選択を検証し、ルームの条件付き更新で最後の提出と締切を整合させる。公開フェーズでは今回のカードを公開し、得点判定への移行で累計を更新する。その後に次ターンまたは最終結果へ進む。最終結果と履歴保存は共通のD1バッチで処理する。

APIでは本人に限り残り手札と選択カードを返す。その他に見える情報は選択済みの印、現在の場、昇順の公開済み得点カード、公開フェーズ以降の各カードとその結果。過去の選択履歴や山札順は表示データと履歴に含めない。`web/number-clash.js` は表示領域と長押しボタンを対戦中に維持し、進行中に下部の内容だけを更新する。長押しの処理はTier表と共用する。最終結果と履歴詳細は同じランキング表示を使う。

### せーので四目

`server/four.js` はターン開始・受付終了と提出順の検証を `server/timed-turn.js` から共用する。全員提出・時間切れの時点で締め切り、D1の条件付き更新で盤面・落下イベント・勝敗・次の受付時刻をまとめて確定する。受付中は本人の列と全員の提出状況だけを返す。時間切れの選択は落下前に空いている列から抽選し、競合時も確定する盤面は一つ。満杯時の処理は `resolveDrop` に置く。

`web/four.js` は同期済みのサーバー時刻と結果を使って順次落下を再生する。同期が遅れた場合は現在の位置から描画し、再接続時は最新盤面を復元する。進行は既存のルーム同期・操作からサーバーが進め、端末からの演出完了通知を要しない。全員の同期が途絶え、次のターンの締切も過ぎていれば、復帰後の同期時刻を起点に受付を再開する。結果は既存の履歴保存処理で書き込み、コマの中間状態や提出は履歴に保存しない。盤面と勝利マスの表示は結果と履歴で共用する。

アイコン右下の色付きマーカーは `player-display.js` の任意の表示項目で、コマの色に名前とチェックの文字色を添えて指定する。コマの色は既存のアバターIDや接続管理用の色スロットとは独立している。

## 同期とクライアント

`web/sync.js` を全画面で共有する。入室前は公開版の確認のみ60秒間隔、ロビー・設定・最終結果は約1.4秒間隔、対戦中は約450ms間隔、バックグラウンドは約4.8秒間隔。復帰時はすぐに同期し、失敗時は段階的に間隔を伸ばす。ルームリビジョンと接続中プレイヤーのビットマスクが変わらない場合は、対戦データを再送しない。ゲーム個別のポーリングは設けない。

`web/player-profile.js` はクライアントとサーバーが共有するアイコンID、レガシー表示、名前の正規化と検証を持つ。新規入室の上限は8コードポイント。9〜20文字はサーバーが既存セッションへの同名復帰か判定する。接続中はルームのアイコンを同期し、結果と履歴は対戦開始時のアイコンを参照する。

`web/player-display.js` は共通のアイコン描画、選択グリッド、選択可能なプレイヤー表示、状態マーク、属性、得点を担当する。各ゲームは表示する対象と状態を渡す。CSSのコンテナ単位で、ビューポートと列数が決めるセル幅・高さにアイコン、文字、余白を合わせる。テキスト実幅を基に長い名前や複数属性を縮め、描画結果をプレイヤー列の高さ計算に使わない。

`web/app.js` が共通の入室・ヘッダー・結果操作を調整する。`web/dialogs.js` は共通メニュー、ゲーム設定、履歴、アップデート情報などを担当する。ルール・対戦履歴・アップデート情報は開いた時点のゲームを表示状態に保持する。履歴の取得時はその範囲をAPIに渡し、省略した従来クライアントには現在の画面の範囲を返す。

## 新しいゲームを追加する

1. `web/games.js` に固定ID・表示名・対応人数（必要に応じてモード別上限）を登録し、ロビー用の画像を設定する。表示名を変えてもIDを維持する。
2. 対戦ルールと参加者別の表示処理をゲーム固有のモジュールに置く。`server/game.js` に開始条件・操作・終了の処理を接続する。ゲーム固有設定は既存のルームJSONから読み込み、旧データの既定値を定義する。
3. 共通画面からゲーム設定とプレイ画面を呼び出す。プレイヤー表示は共通コンポーネントを使い、状態マークをゲーム本体に重複表示しない。画面遷移と通信は共通の状態同期を使う。
4. `server/history.js` と `web/history.js` にスナップショットと詳細表示を追加する。過去レコードが読み込めることを確認する。
5. 回帰テスト、スマートフォン縦画面の確認、アップデート情報の更新を行う。
